# eventd OpenAI 决策评测

2026-11-07。第二轮三个模型各有 30 条有效响应，漏唤醒均为 0；`gpt-6-luna` 在本小样本中误唤醒最少，暂推荐用于进一步验证，不能据此保证生产安全。当前交付协议仍存在崩溃后重复交付窗口，详见 README。

## 方法与预先标注

固定 30 个规则层无法直接判断的事件，调用前标注期望：14 个 `wake`、16 个非唤醒（`defer` 或 `ignore` 均计正确）。两个来自真实日志的心跳事件预期不唤醒；其余为手工案例。真实内容不保存或展示，抽样规模很小，期望标签为人工判断而非独立复核的金标准。

| ID | 脱敏事件描述 | 期望 |
| --- | --- | --- |
| W01–W07 | 发布审批受阻；疑似泄密；不可逆删除待确认；预算即将耗尽；工作冲突；外部系统停摆；关键安全缺陷 | wake |
| W08–W11 | 长期无进展需干预；等待统筹决策；重试耗尽；全员死锁 | wake |
| W12–W14 | 关键交付缺失；核心需求失败阻塞后续；临近截止须重新分配 | wake |
| N01–N07 | 扫描误报；未使用依赖警告；限流已恢复；测试夹具告警；阈值配置已纠正；风险已解决；调试信息误报 | 非唤醒 |
| N08–N11 | 按计划等待重试；长测试持续输出；网络短暂停顿后恢复；构建正常推进 | 非唤醒 |
| N12–N14 | 可选文档待补；非关键测试待完成；可选润色推迟 | 非唤醒 |
| N15–N16 | 两条真实日志中的心跳 | 非唤醒 |

评测使用与 eventd 相同的提示词、严格 JSON schema 和无工具 Responses API，空上下文，输出上限 512 token；每个案例独立调用。将非唤醒的预期与实际 `wake` 计为误唤醒，将预期 `wake` 与实际非唤醒计为漏唤醒。延迟为单次请求平均墙钟时间，含并发及网络影响；非生产负载基准。输入 token 按未缓存价保守估算，不扣除可能的缓存折扣。

账户费用接口返回 **HTTP 403**，错误 code 未返回；因此无法独立确认账单扣费、额度扣减或实际总费用。Responses API 返回 HTTP 200、有效结果和 token 用量，说明请求成功，但不等于已核实扣款。由于真实样本仅两个且标签未独立复核，推荐结论应通过更多真实事件、人工复核和实际消费者链路验证后再采用。
