# M10 #62: accessibility findings 12-14

Repository: OpenBot desktop (Electron, Bun, TypeScript, SolidJS). Read AGENTS.md and the AGENTS.md of every

## Scope

Accessibility findings 12, 13 and 14 below (tab hint uses aria-description; role=application over a region of controls; switch field reads in the opposite order). Your base already contains your fixes for findings 1-11 and 15. Keep visuals and mouse behavior unchanged.

## Findings (from an audit written before the upstream sync; file and line references may have moved)

### 12. The tab hint uses `aria-description`, which no screen reader reads

**Evidence**

- `packages/ui/src/features/browser/BrowserTabStrip.tsx:439`:
  `aria-description={canClose() ? t("browser.tab.closeHint") : undefined}`.

**Why it matters**

`aria-description` is an ARIA 1.3 attribute. No current screen reader exposes it, so the hint
"press Delete to close" never reaches the user. This breaks WCAG 4.1.2 Name, Role, Value (level A)
and WCAG 3.3.2 Labels or Instructions (level A).

**Fix**

Render the hint in a `<span id="...">` inside the tab and point `aria-describedby` at it.

**Size** S.

### 13. `role="application"` covers a region full of controls

**Evidence**

- `packages/ui/src/features/diagrams/DiagramBoard.tsx:462`: the board is `role="application"`. The
  board holds node buttons, port buttons and edge buttons
  (`packages/ui/src/features/diagrams/DiagramNodeCard.tsx:105-172`,
  `packages/ui/src/features/diagrams/DiagramBoard.tsx:578-589`).
- `packages/ui/src/features/conversation/DiagramCanvas.tsx:149`: the image canvas is
  `role="application"`.

**Why it matters**

`role="application"` turns off the browse mode of the screen reader over the whole region. The
user can no longer read the board and find the controls by reading. Only the custom arrow-key
panning works. A `role="group"` with a label gives the same keyboard result and keeps the content
readable. This breaks WCAG 4.1.2 Name, Role, Value (level A).

**Fix**

Use `role="group"` with the same `aria-label`, and keep the `onKeyDown` handler. If a screen
reader must pass the arrow keys through, put the role on a small inner element that holds only the
canvas surface, not on the region that holds the nodes.

**Size** M.

### 14. The switch field reads in the opposite order to the screen

**Evidence**

- `packages/ui/src/features/conversation/styles/agent-settings.css:314-319`: the rule reverses the
  row. The comment says "the shared field puts the label first … Here the switch comes first".
- `packages/ui/src/switch.tsx:287-289`: the DOM puts `<label>` before the switch input.
- `src/renderer/src/features/conversation/AgentRoutinesSettings.tsx:816-821`: the use of the field.

**Why it matters**

The eye sees the switch first and the state word second. The screen reader reads the state word
first and the switch second. The two orders do not match. This breaks WCAG 1.3.2 Meaningful
Sequence (level A).

**Fix**

For this one variant, put the switch before the label in the DOM, or drop `row-reverse` and let
the label come first.

**Size** S.
