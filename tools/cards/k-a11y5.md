## Findings (from an audit written before the upstream sync; references may have moved)

### 9. The pinned tile reorder shortcut is not published

**Evidence**

- `packages/ui/src/features/sidebar/SidebarPinnedGroup.tsx:99-107`: the key handler is on the
  `<li>`. No `aria-keyshortcuts` appears in the file.
- `packages/ui/src/features/sidebar/SidebarPeopleSection.tsx:69`: the people rows do publish
  `aria-keyshortcuts="Alt+ArrowUp Alt+ArrowDown"`.
- `packages/ui/src/features/servers/ServerRail.tsx:408`: the server rail publishes
  `aria-keyshortcuts`.

**Why it matters**

A screen reader user cannot discover the reorder shortcut, because the platform never announces
it. The feature is present but hidden. This breaks WCAG 4.1.2 Name, Role, Value (level A).

**Fix**

Add `aria-keyshortcuts="Alt+ArrowLeft Alt+ArrowRight"` to the pinned tile button in
`packages/ui/src/features/sidebar/SidebarPinnedGroup.tsx`, the way the people row does.

**Size** S.

### 10. Nine toggles report `aria-expanded` with no `aria-controls`

**Evidence**

- `packages/ui/src/features/conversation/SidePanel.tsx:82`
- `packages/ui/src/features/conversation/ConversationHeader.tsx:71`
- `packages/ui/src/features/conversation/ChatActionMarker.tsx:505`
- `packages/ui/src/features/conversation/SelectionActions.tsx:537`
- `packages/ui/src/features/conversation/RoutineWebhookTrigger.tsx:202`
- `packages/ui/src/features/diagrams/DiagramView.tsx:178`
- `packages/ui/src/features/agents/AgentTemplateSections.tsx:89`
- `packages/ui/src/features/transfer/InstanceTransferView.tsx:197`
- `src/renderer/src/features/servers/ServerMembersSection.tsx:513`

**Why it matters**

The user hears "collapsed" or "expanded", but the platform cannot say what changed. The screen
reader user must hunt for the region. This breaks WCAG 4.1.2 Name, Role, Value (level A).

**Fix**

Give the panel an `id`, and set `aria-controls` on the toggle that opens it.

**Size** M for the nine. S for one.

### 11. Four buttons that open a dialog do not report their state

**Evidence**

- `packages/ui/src/components/ProviderPicker.tsx:1042`
- `packages/ui/src/features/sidebar/SidebarSearch.tsx:18`
- `packages/ui/src/features/sidebar/SidebarSearch.tsx:31`
- `packages/ui/src/features/conversation/AgentSettingsPanel.tsx:1378`

**Why it matters**

Each of these has `aria-haspopup="dialog"` and no `aria-expanded`. The state of the trigger is
missing. This breaks WCAG 4.1.2 Name, Role, Value (level A).

**Fix**

Bind `aria-expanded` to the open state of the dialog that the button opens.

**Size** S.
