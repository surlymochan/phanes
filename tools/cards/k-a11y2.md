## Findings (from an audit written before the upstream sync; references may have moved)

### 2. A chat in a sidebar section can only be moved by dragging

**Evidence**

- `packages/ui/src/features/sidebar/SidebarAgentRow.tsx:188` and
  `packages/ui/src/features/sidebar/SidebarChannelRow.tsx:47`: the row wrapper is `draggable` and
  starts a drag. There is no key handler in either file.
- `packages/ui/src/features/sidebar/SidebarPinnedGroup.tsx:99-107`: a pinned tile moves with
  `Alt+ArrowLeft` and `Alt+ArrowRight`.
- `packages/ui/src/features/sidebar/SidebarPeopleSection.tsx:78-87`: a person row moves with
  `Alt+ArrowUp` and `Alt+ArrowDown`.
- `packages/ui/src/features/sidebar/stores/layout-actions.ts:165-210`: `moveChatAction` computes a
  chat move, and `packages/ui/src/features/sidebar/stores/layout-actions.ts:273` has
  `movePinnedItem`. There is no `moveChatByKeyboard`.

**Why it matters**

The order of the chats in a section is a layout that the user controls. Two of the three sidebar
groups have a keyboard path and one does not. A keyboard user cannot put a chat in the place they
want it. This breaks WCAG 2.1.1 Keyboard (level A).

**Fix**

Add `moveChatByKeyboard(chatId, direction)` next to `movePinnedItem` in
`packages/ui/src/features/sidebar/stores/layout-actions.ts`, publish it through
`packages/ui/src/features/sidebar/sidebar-scope.ts:74`, and call it from an `onKeyDown` on the row
button in `packages/ui/src/features/sidebar/SidebarAgentRow.tsx` and
`packages/ui/src/features/sidebar/SidebarChannelRow.tsx`. Use `Alt+ArrowUp` and `Alt+ArrowDown`,
the same keys as the people rows.

**Size** M.

### 3. The chat state and the unread count are not in the accessible name of a sidebar row

**Evidence**

- `packages/ui/src/features/sidebar/SidebarAgentRow.tsx:103`: the button carries an `aria-label`
  built from the name, the title, the preview and `stateLabel()`.
- `packages/ui/src/features/sidebar/SidebarAgentRow.tsx:75-80`: `stateLabel()` returns a text only
  for the `routine`, `waiting` and `limited` states. The `unread`, `working` and `responded` states
  return an empty string.
- `packages/ui/src/features/sidebar/SidebarAgentIndicator.tsx:33-41`: the badge that holds the count
  is `aria-hidden="true"`.
- `packages/ui/src/features/sidebar/SidebarAgentRow.tsx:169`: the `sr-only` span that holds the
  state text sits inside the button, so the `aria-label` replaces it in the name.
- `packages/ui/src/features/sidebar/SidebarChannelRow.tsx:63,73,97`: the same for a channel.
- `packages/ui/src/features/sidebar/SidebarPeopleSection.tsx:68,92`: a person row has the
  `aria-hidden` badge and no text alternative at all.

**Why it matters**

An `aria-label` replaces the content of a button when the name is computed. A screen reader user
who tabs through the sidebar hears "Nightly report, last message text" and never hears that three
new messages arrived. The count is on screen as a coloured number. This breaks WCAG 4.1.2 Name,
Role, Value (level A) and WCAG 1.3.1 Info and Relationships (level A).

**Fix**

Put the state in the `aria-label`, the way
`packages/ui/src/features/sidebar/SidebarPinnedGroup.tsx:74-79` already does with
`sidebar.pinned.agentWithState`. Give the people row the same `sr-only` text that the agent row
has at `packages/ui/src/features/sidebar/SidebarAgentRow.tsx:169`.

**Size** M.
