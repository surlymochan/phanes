## 一、产出与校验概况

1. **执行命令**：
   ```bash
   cd openbot/examples/org-health-local
   python3 da/build_diagnosis.py --brief demo/brief.json --raw da/sample-raw --out demo/diagnosis.json
   ```
2. **校验结果**：
   ```bash
   python3 validate.py demo/diagnosis.json
   # 输出：demo/diagnosis.json: 校验通过
   ```
   快照完全符合 `schema/diagnosis.schema.json`（schema v4 规范），零校验报错。
3. **核心元数据**：
   - 来源字段路径 `scope.来源`：`"合成示例数据"`
   - 观察月份 `scope.观察月份`：`"2026-09"`
   - 数据截止 `scope.数据截止`：`"2026-09-30"`
   - 产出标识 `origin`：`"DA 快照（合成示例原始数据，按任务书口径计算）"`
   - 角色元数据 `producer`：`"da"`；`periods`：`["2026-01", "2026-05", "2026-09"]`（沿用任务书声明的 periods，供 Reviewer 核对交接链）

## 二、口径说明与缺失处理（引用 `diagnosis.json` 中的 `口径说明` 字段）

快照在顶层通过 `口径说明`（字段路径 `口径说明`）完整记录了计算与呈现口径：
- `口径说明[0]`：目标与基准说明，以 2026 H1（`2026-05H1参考`）为冻结对照基准；
- `口径说明[1]`：期次性质划分：`2026-01` 与 `2026-09` 为已发生实际期次，`2026-05` 为 H1 参考期次，`年末测算` 与 `年末目标` 为前瞻预算与目标估算；
- `口径说明[2]`：单位口径：技术人力成本为万元/月（不含运维与设施）；折算人头为当量折算值（非自然人数）；收入为万美元/月；成本率为成本占同期收入按汇率折人民币的比例；
- `口径说明[3]`：汇率 7.2 人民币/美元，数据截止 2026-09-30；
- `口径说明[4]`：`null` 含义统一为“未统计、未提供或无同口径对比数据”，前端页面显示为「未提供」，不以 0 或推测值替代；
- `口径说明[5-9]`：逐项记录原始数据缺失期次：
  - `口径说明[5]`：`"整体技术人力成本 缺 2026-05 数据，按 null 处理"`
  - `口径说明[6]`：`"营收业务技术人力成本 缺 2026-05 数据，按 null 处理"`

## 三、必答问题逐条回答（逐条引用 `diagnosis.json` 字段路径与数值）

### 问题 1：观察期间内整体技术人力成本是多少？相对期初实际增减多少（金额与百分比）？

- **对应指标与字段路径**：`metrics[0]`（标题：`metrics[0].标题` = `"整体技术人力成本"`），数值路径为 `metrics[0].数值`
- **各期次具体数值**：
  - `metrics[0].数值["2026-01实际"]`：`10.4` 万元/月（期初实际）
  - `metrics[0].数值["2026-05H1参考"]`：`null`（**本期数据不足**：原始数据未提供 2026-05 单独拆分的整体成本）
  - `metrics[0].数值["2026-09实际"]`：`12.4` 万元/月（期末实际）
  - `metrics[0].数值["年末测算"]`：`13.4` 万元/月（前瞻测算值，非已发生实际）
- **相对期初实际（2026-01实际 = 10.4 万元/月）增减情况**：
  - **2026-09实际（期末实际）**：增加 `+2.0 万元/月`（12.4 - 10.4），增幅为 `+19.2%`（引用 `insights[4].内容`：“整体技术人力成本增幅 19.2%”）；
  - **年末测算**：增加 `+3.0 万元/月`（13.4 - 10.4），增幅为 `+28.8%`；
  - **2026-05H1参考**：**本期数据不足**，值为 `null`，无法计算增减金额与比例。

### 问题 2：整体折算人头的变化与整体技术人力成本的变化是否同向？折算人头口径是否与成本口径一致？

- **对应指标与字段路径**：
  - 整体折算人头：`metrics[1]`（标题：`metrics[1].标题` = `"整体折算人头"`），数值路径为 `metrics[1].数值`
  - 整体技术人力成本：`metrics[0].数值`
- **各期次折算人头数值**：
  - `metrics[1].数值["2026-01实际"]`：`10.4` 人（当量）
  - `metrics[1].数值["2026-05H1参考"]`：`null`（**本期数据不足**）
  - `metrics[1].数值["2026-09实际"]`：`12.4` 人（当量）
  - `metrics[1].数值["年末测算"]`：`13.4` 人（当量）
- **同向性回答**：
  **完全同向**。从 `2026-01实际` 到 `2026-09实际`，折算人头由 10.4 人（当量）增至 12.4 人（当量），净增 2.0 当量（+19.2%）；整体技术人力成本同期由 10.4 万元/月增至 12.4 万元/月，净增 2.0 万元/月（+19.2%），两者同向同幅度增长（引用 `insights[0]` 与 `insights[1]`）。年末测算亦同向增至 13.4。
- **口径一致性回答**：
  **口径完全一致**。引用 `definitions[0]`、`口径说明[2]` 及任务书定义：折算人头为按投入当量折算的人数，非自然人数；与成本口径同源同范围，均不含运维与设施。在缺失期次（`2026-05H1参考`）两者同为 `null`，不以其他值替代。

### 问题 6：哪些结论只能由聚合口径支撑，哪些领域因缺少证据而无法回答？

- **只能由聚合口径支撑的结论**：
  1. 整体与营收业务技术人力成本及折算人头规模与增幅（10.4 → 12.4 万元/月，10.4 → 12.4 当量，增幅 +19.2%）；
  2. 成本增速（+19.2%）低于同期收入增速（+21.4%），整体成本率保持平稳（约12.9% → 约12.7%）（引用 `insights[4]`）；
  3. 营收业务成本占比保持在 79.8%，投入结构未发生偏移（引用 `insights[5]`）。
  *注：以上结论仅在组织/业务线聚合层面成立，不得穿透下钻为员工个体、薪酬明细或自然编制结论。*
- **因缺少证据而无法回答的领域（均属于“本期数据不足”，不得编造）**：
  1. **2026-05（H1参考基准期）的实际同口径水平**：**本期数据不足**。原始数据缺 2026-05 整体与营收业务人力成本、运维设施成本及折算人头（引用 `risks[0]` 与 `recommendations[0]`，缺失证据：“2026-05 的整体技术人力成本、折算人头与营收业务技术人力成本明细”）。
  2. **年末全口径技术成本率的测算值**：**本期数据不足**。`forecast.csv` 缺少年末运维与设施成本口径（引用 `risks[1]` 与 `recommendations[1]`，缺失证据：“年末运维与设施成本的预算或测算口径说明”）。
  3. **收入年末测算（14.8）与年末目标（15.2）的差异成因**：**本期数据不足**。缺少目标制定依据、测算假设与两者换算说明文档（引用 `risks[2]` 与 `recommendations[2]`）。
  4. **未覆盖月份（2026-02 ~ 2026-04、2026-06 ~ 2026-08）对期间波动的影响**：**本期数据不足**。各表覆盖期次不一致，缺乏逐月完整明细（引用 `risks[3]` 与 `recommendations[3]`）。
  5. **个人级、薪酬结构、编制合规判断**：**本期数据不足且禁止**。严格遵循任务书禁止事项（`brief.json` 禁止事项），只出聚合口径。

## 四、已知问题与脚本 Bug 记录（严格遵守“不改 brief.json，不改脚本”）

1. **`da/write_method.py` 无法直接消费 schema v4 任务书（已修复，Refs #736）**：
   - **原现象**：执行 `python3 da/write_method.py --brief demo/brief.json --data demo/diagnosis.json --out demo/method.md` 时报错退出（退出码 1），输出信息：
     ```text
     生成文档包含诊断数值：0、2026
     ```
   - **根因分析**：
     - `da/write_method.py`（#82）编写时针对旧版简单列表结构的 brief（`观察期间: ["一月", "二月"]`）；
     - Boss #103 产出的 `demo/brief.json`（schema v4）中，`观察期间` 为字典结构 `{"观察月份": "2026-09", "数据截止": "2026-09-30", "期次": [...]}`，`口径` 为嵌套字典；
     - `write_method.py:98-103` 与 `write_method.py:166-171` 在做期次文本替换时，未递归解包字典，把字典 repr 整体拼接输出（包含 `'2026-09'`），随后 `numeric_literals` 提取了年份 `2026` 与数字 `0`，触发泄露检查正则；
     - 另外，`build_diagnosis.py`（在 #125）已内建生成完整的 `口径说明` 字段并直接写入 `diagnosis.json`（符合 `schema/diagnosis.schema.json` 定义），故快照本身已包含完整口径与缺失期次说明。按规则记录 bug，不改动脚本与 brief.json。
   - **修复现状**：`da/write_method.py` 现按字段展开 `观察期间` 与嵌套 `口径`，泄露比对只取指标数值与结论里的数字（口径文案里的“不以 0 或推测值替代”不是诊断数值），期次标签按结构排除；结论数值即使被写进任务书口径也按数值泄露失败；同一命令现在退出码为 0，生成的方法说明按指标标题引用任务书 `口径` 的同名条目并写明字段路径与 `null` 期次。
2. **Boss 任务书与站点页面期次键保持对齐**：
