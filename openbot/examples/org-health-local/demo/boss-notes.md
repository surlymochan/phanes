# Boss 任务书说明：2026 H1 组织健康度诊断（合成数据演示）

> **合成数据演示，不含真实员工数据**：本次任务书与后续诊断只使用仓库内人工构造的合成样本（`openbot/examples/org-health-local/da/sample-raw/`），结论不用于判断任何真实组织，仓库内不写入真实数字。

## 任务书要点（与 `demo/brief.json` 一致）

1. 生成（脚本未改动；产物 `demo/brief.json` 的 `schema版本` 为 4，可逐字复现）：`cd openbot/examples/org-health-local && python3 boss/make_brief.py --out demo/brief.json --goal "以 2026 H1（2026-05H1参考）为冻结对照基准，复核观察期间内整体技术人力成本与折算人头的水平与变化幅度（合成数据演示）。" --goal "说明营收业务（含共享平台）口径的成本、折算人头与收入的匹配情况。" --goal "给出整体、营收业务与全口径三个成本率的水平，并解释差异来源。" --goal "列明缺少同口径数据的期次与领域，说明缺口对上述结论的影响。"`
2. 目标（4 条）：以 2026 H1（2026-05H1参考）为冻结对照基准，复核观察期间内整体技术人力成本与折算人头的水平与变化幅度（合成数据演示）。说明营收业务（含共享平台）口径的成本、折算人头与收入的匹配情况。给出整体、营收业务与全口径三个成本率的水平，并解释差异来源。列明缺少同口径数据的期次与领域，说明缺口对上述结论的影响。
3. 观察期间：观察月份 2026-09，数据截止 2026-09-30；期次 2026-01实际、2026-05H1参考、2026-09实际、年末测算、年末目标。2026-01实际 与 2026-09实际 为已发生实际期次，2026-05H1参考 为 H1 冻结对照基准，年末测算与年末目标为前瞻预算与目标估算，不代表已发生实际。
4. 口径：整体技术人力成本（万元/月，不含运维与设施）；整体折算人头（人当量，非自然人数，与成本口径同源同范围）；营收业务（含共享平台）技术人力成本与折算人头（万元/月、人当量，与整体口径同定义、不同范围）；收入与成本率（收入万美元/月，成本率 = 技术人力成本 ÷ 同期收入折算为同一币种，全口径另含运维与设施）。缺同口径取数的期次写 `null`，页面显示「未提供」，不以 0 或推测值替代。
5. 数据需求（6 条）：月度成本/技术人力成本、月度人力/折算人头、月度成本/营收业务技术人力成本、月度人力/营收业务折算人头、月度收入/营收业务收入、月度成本/运维与设施成本（字段路径为逻辑路径，原始表列名由 DA 按实际来源映射）。
6. 校验：`python3 -c "import json;b=json.load(open('demo/brief.json'));assert str(b.get('schema版本'))=='4' and b.get('必答问题')"`。

## 必答问题（逐条，与「必答问题」一致）

1. 观察期间内整体技术人力成本是多少？相对期初实际增减多少（金额与百分比）？
2. 整体折算人头的变化与整体技术人力成本的变化是否同向？折算人头口径是否与成本口径一致？
3. 营收业务（含共享平台）的技术人力成本与折算人头分别是多少？占整体口径的比例是多少？
4. 观察期间的收入是多少（万美元/月）？整体技术人力成本率与营收业务技术人力成本率各是多少？
5. 全口径技术成本率（含运维与设施）在哪些期次有同口径值？缺同口径值的期次如何呈现？
6. 哪些结论只能由聚合口径支撑，哪些领域因缺少证据而无法回答？

## 禁止事项（逐条，与「禁止事项」一致）

- 不得写入真实组织数据：任务书只写口径、问题与字段映射，真实数字与明细只留在仓库外的工作目录。
- 不作个人/薪酬/编制判断：只输出聚合口径，不含个人级字段、薪酬明细与编制明细。
- 不得编造数字：没有取数支撑的值一律写 null，并在 risks/recommendations 的“缺失证据”里写明缺口。
- 不得改动指标标题与顺序：metrics 的四个标题与顺序与站点期望一致，改动会被页面判为结构错误。
- 不得把推断写成事实：洞察按“事实/推断/边界”标注，推断必须写明依据与核实方式。
- 不得把仓库外的真实数据复制进仓库：诊断 JSON 写在仓库外，交接只给路径与校验值。

## 已知问题（按要求只记录，不改脚本）

1. **Boss 任务书与 DA 脚本的期间字段不互通**：`da/build_diagnosis.py:139-159` 要求任务书带 `观察期间.起始期次/参考期次/截止期次`，而 `boss/brief.schema.json:59-89` 把 `观察期间` 固定为 `观察月份/数据截止/期次/说明`（`additionalProperties: false`），直接喂入 `demo/brief.json` 会报「任务书 `观察期间` 缺少起始期次或截止期次」。
2. **汇率字段无处可放**：`da/build_diagnosis.py:175-189` 要求 `口径.汇率`（正数，人民币/美元）才能算成本率，而 `boss/brief.schema.json:90-114` 的 `口径` 只允许四个指标标题，补齐期次后仍报「任务书 `口径.汇率` 缺失或不是正数，无法计算成本率」。两处都要在 DA 侧做字段映射/适配，本次不改脚本。
3. **观察月份取默认 2026-09**：站点前端硬编码观察月份与期次键（`openbot/examples/org-health-local/app.js:58-59`、`app.js:75`、`app.js:110`），若改用 `--month 2026-06` 则与页面期望不一致、会被判结构错误；因此本次演示里的「2026 H1」体现为 `2026-05H1参考` 这一 H1 冻结对照基准。
