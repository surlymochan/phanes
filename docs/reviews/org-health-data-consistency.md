### 1.2 发现的问题与分析

#### 问题 1：成本率比率计算与底层数值严重冲突（ISSUE-07）
- **位置**：`openbot/examples/org-health-local/data/diagnosis.json` 第 62–77 行。
- **现状**：
  - 口径说明（第 10 行）明确指出：“技术人力成本单位为万元/月... 收入单位为万美元/月；成本率为成本占同期收入折人民币比例”。
  - 以 2026-01实际 为例：技术人力成本为 `10 万元/月`，收入为 `10 万美元/月`。按当前系统标准汇率 7.2 计算，折合人民币收入为 `72 万元/月`。
  - 理论整体技术人力成本率应为：`10 / 72 ≈ 13.89%`。若汇率按 1:1 不折算，成本率应为 `10 / 10 = 100%`。
  - 但 JSON 中填入的值为 `"约1%"`；同理，2026-09实际（12 万元 / 12 万美元）填入 `"约2%"`，年末测算（14 万元 / 14 万美元）填入 `"约3%"`。
- **影响**：数值完全是拍脑袋填写的占位字符，破坏了演示数据在页面展示时的合理性与信度。
- **建议改法**：按标准汇率 7.2 重新核算比率字符串（如 2026-01 为 `"约13.9%"`，2026-09 为 `"约13.9%"` 或采用符合演示梯度的合理收入数值）。

#### 问题 2：分部数据与整体数据完全重合，全口径成本率未体现额外成本（ISSUE-08）
- **位置**：`openbot/examples/org-health-local/data/diagnosis.json` 第 36–51 行及第 74–77 行。
- **现状**：
  - 整体技术人力成本（10, null, 12, 14）与营收业务技术人力成本（10, null, 12, 14）在所有期次完全相等，折算人头亦然（均一致为 10, null, 12, 14），即营收业务占比恒等于 100%。
  - 全口径技术成本率（含运维设施）在 2026-01实际 为 `"约1%"`，2026-09实际 为 `"约2%"`，与不含运维设施的整体技术人力成本率（约1%、约2%）毫无差异。
- **影响**：无法体现“分业务口径拆分”和“全口径包含运维设施”的诊断对比价值。
- **建议改法**：建议将 `data/diagnosis.json` 对齐 `demo/diagnosis.json` 中的合成基准数据（如整体成本 10.4、12.4，营收业务成本 8.3、9.9，全口径成本率 15.5%、15.2% 等）。

#### 问题 3：文字洞察与指标数据零交互（ISSUE-10）
- **位置**：`openbot/examples/org-health-local/data/diagnosis.json` 第 81–103 行。
- **现状**：
  - `insights` 仅有一条“此处只展示人工构造的数据。”，`recommendations` 仅有一条“补充证据”。
  - 文字未提及指标中的任何数字（如 10、12 万元，1%、2% 等），没有定量结论。
- **建议改法**：若该文件继续作为静态演示模板，应补全带具体指标数值与单位的参考洞察与建议。

### 2.3 问答类洞察严重缺陷排查（Insights 10-15）

该部分为 `da/build_diagnosis.py` 的 `answer_question()` 针对任务书必答问题自动生成的回答。由于关键词匹配逻辑的严重缺陷，出现了严重的指标与数字不一致、甚至答非所问：

#### 缺陷 1：回答遗漏营收业务成本与占比数值（ISSUE-01）
- **位置**：`demo/diagnosis.json` 第 146–149 行。
- **标题**：“营收业务（含共享平台）的技术人力成本与折算人头分别是多少？占整体口径的比例是多少？”
- **当前内容**：“整体折算人头 10.4 → 12.4；营收业务折算人头 8.3 → 9.9。”
- **问题说明**：
  - 问题明确问了：① 技术人力成本是多少；② 折算人头是多少；③ 占整体口径的比例是多少。
  - 当前内容不仅**完全漏掉了技术人力成本数值（8.3 → 9.9 万元/月）**，也**完全漏掉了占比数字（79.8%）**，却把不相干的整体人头塞了进来。
- **根因分析**：
  - 查看 `da/build_diagnosis.py` 第 723 行：
    ```python
    if "人头" in question:
        return (
            "事实",
            f"整体折算人头 {fmt_number(heads['start'])} → {fmt_number(heads['end'])}；"
            f"营收业务折算人头 {fmt_number(revops_heads['start'])} → {fmt_number(revops_heads['end'])}。",
        )
    ```
  - 因为问题字符串中同时包含“成本”与“人头”，而 `if "人头" in question` 排在 `if "成本" in question` 之前，导致直接命中了人头模板，造成技术人力成本与比例数据全部丢失。
- **建议改法**：
  - 修改 `da/build_diagnosis.py`，增加针对复合问题的专用匹配或更精准的分词判断：
    ```python
    # 建议内容
    f"营收业务技术人力成本 {fmt_number(revops_cost['start'])} → {fmt_number(revops_cost['end'])} 万元/月（占整体 {facts['revops_cost_ratio_start']} → {facts['revops_cost_ratio_end']}）；折算人头 {fmt_number(revops_heads['start'])} → {fmt_number(revops_heads['end'])}。"
    ```
