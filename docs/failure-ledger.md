## Method and limits

- [Claim-time issue input](evidence/failure-ledger/claimed-issues.json), [source comments](evidence/failure-ledger/comments.json), and [selected terminal events](evidence/failure-ledger/primary-events.json) preserve the evidence and allow an offline rerun. The read command was `gh issue list --repo surlymochan/phanes --state all --label lane-failed --limit 1000 --json number,title,body,state,url,labels,closedAt,updatedAt`; comments came from the paginated `/repos/surlymochan/phanes/issues/N/comments` endpoint.
- One row per card, using its latest recorded terminal execution or explicit thin-card rejection before capture. Closure is a follow-up, **not** a diagnosis of an earlier runtime failure. Earlier ended attempts remain in the source archive. In-flight attempts are not inferred from titles or included as failures.
- `quota` includes a recorded `budget_exceeded` stop, not an inferred provider quota. A stop status alone does not establish its cause. A non-quota stop without a diagnostic mechanism is recorded as `no-commit`; this is an observed outcome, not a causal diagnosis. Missing underlying evidence is **未定性** and remains a gap even when the card is closed or a later successor landed.
- Inventory coverage and diagnosis completeness are different. Every card is listed; the checker intentionally exits 1 for undetermined roots. No 100% root-cause claim is made. No audited source issue/PR, label or closure was changed. Only #1776 uses the required lane claim/submission transitions.
- GitHub links are evidence citations, not new operational instructions. Follow-up status records the snapshot; it does not authorize requeue or repair.
