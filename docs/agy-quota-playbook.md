# Fleet: Antigravity 429 配额耗尽运维手册

## 适用场景
在使用 Antigravity CLI 或相关模型接口时，遇到 HTTP 429 错误或提示 `Individual quota reached`（个人配额已达上限）时，按本手册执行应急处置。

---

## 1. 紧急响应与阻断

当发现 `Individual quota reached` 或 429 配额耗尽错误时：

1. **立即停止硬重试**：
   - 严禁通过循环脚本或自动化程序持续硬重试，避免触发账号级严重风控或导致更长时间的封禁/限制。
2. **设置工作流暂停标识**：
   - 根据当前运行的 Lane/Worker 实例，在工作目录或指定状态目录下创建对应的暂停文件（如 `touch PAUSE-A1` 或 `touch PAUSE-A2`）：
     ```bash
     touch PAUSE-A1
     # 或
     touch PAUSE-A2
     ```
   - 调度进程或守护进程检测到该标志后应主动暂停任务分发与执行。
3. **通知主理人介入换账号**：
   - 收集错误日志片段、账号标识及发生时间。
   - 立即向主理人发送告警通知，请求主理人轮换可用账号或分配新的 API 密钥/凭证。

---

## 2. 账号轮换与凭证切换

由主理人或授权运维人员执行账号切换：

1. 确认新的有效账号已具备充足配额。
2. 更新运行环境中的认证信息或登录状态（如重新执行认证登录命令或更新环境变量/凭据文件）。
3. 验证新凭证的连通性与模型调用有效性（单次探活调用）。

---

## 3. 恢复与解封步骤

确认新账号生效且调用正常后，按以下步骤恢复业务：

1. **清理暂停标志**：
   - 移除此前设置的暂停文件：
     ```bash
     rm -f PAUSE-A1 PAUSE-A2
     ```
2. **恢复任务执行**：
   - 重启或唤醒暂停的 Lane/Worker 实例。
   - 观察首批任务的执行日志与返回状态。
3. **监控与复盘**：
   - 密切监控 5-15 分钟内的调用频率与配额消耗情况。
   - 记录配额耗尽事件及恢复耗时，更新配额水位告警阈值。
