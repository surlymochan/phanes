# OpenSwarm guard：shell_invocations 与 event_commands 纯单元测试
labels: p2,backend:codex
新建 `openswarm/tests/test_exec_commands.py`，用 `openswarm/tests/_load.py` 的 `load()` 载入 `openswarm/bin/openswarm`，补两个纯函数的单元测试（只做文本解析，不起进程、不联网）：

① `shell_invocations`（第 4034-4068 行）：`a; b` 被切成两段并各自产出一条；`cd /tmp && ls` 里 `cd` 之后的命令拿到更新后的 cwd；`sh -c "rm -rf /"` 会递归产出内层命令；`FOO=1 env ls` 这类赋值与环境前缀被跳过、命令名仍是 `ls`；引号里的分号不被当作分隔符；递归深度超过 16 层时停止产出。
② `event_commands`（第 3987-4032 行）：从 `method == "session/update"` 且 `sessionUpdate` 为 `tool_call`/`tool_call_update` 的事件、`method == "item/commandExecution/requestApproval"` 的事件、`type == "tool_call"`/`"tool_use"` 的事件、`type == "assistant"` 且 content 里含 `tool_use` 的事件里取出命令字符串；`session/update` 但 `sessionUpdate` 不是上述两种时返回空列表；`arguments`/`rawInput`/`input`/`args` 字段里的 JSON 字符串会被继续解析；返回结果去重且保持出现顺序。

边界：只新建测试文件，不改 `openswarm/bin/openswarm`；不依赖任何其它待办任务。

验收：`python3 openswarm/tests/test_exec_commands.py`
