# backlog 任务卡规范

本目录只收录能够推动真实行为改进的任务卡。写卡前先检查 `docs/backlog/next/`，避免与已有主题重复；同一缺口已有卡时，应补充原卡或说明新的边界，而不是换标题重写。

## 必须满足

- 每张卡的预期改动至少 **30 LOC**。这里的 LOC 指实现、测试或配置中可审查的有效行数，不包括重复描述、空白行和机械生成内容。
- 每卡必须同时写清成功路径和失败路径：成功时观察到什么行为，失败、异常、拒绝或资源不可用时应如何表现，以及各自的断言或验收命令。
- 任务目标必须落到具体文件、入口、接口或用户可观察行为，并说明不应扩大到哪些范围。
- 验收命令必须可在本地重复运行；涉及回归时优先引用真实测试入口，而不是只检查文件存在或字符串存在。
- 卡片应说明相关现状、最小实现边界和可验证结果；不能把探索、想法或“后续再补”当作完成标准。

## 明确禁止

- **禁止 README-only**：只新增 README、注释、说明文字或文档链接，不能作为独立任务卡交付，除非任务本身明确要求维护规范且同时有可验证的规则或工具行为变化。
- **禁止空输入边界模板**：不能仅为 `[]`、`{}`、空 ledger、缺少一行或其他空输入补一个模板化测试；必须证明它对应真实调用链、故障风险或用户行为，并覆盖有意义的成功与失败结果。
- **禁止重复主题**：不得复制已有卡片、仅替换组件名/时间戳/标题，或把同一行为拆成没有独立价值的多张卡。重复卡应合并、关闭或在卡中说明新增差异。
- **禁止空壳测试**：不得只断言“不抛异常”、固定字符串、文件存在、分支被执行，或通过 mock 绕开被测行为；断言必须能区分正确实现与错误实现。
- **禁止伪造完成量**：不得用大段重复快照、生成文件、格式化噪声或无意义样例凑够 30 LOC。

## 优先级方向

优先补齐**双模式**缺口：同一能力在本地/远端、同步/异步、命令行/API 或其他项目既定的两种运行模式下，应有一致且可解释的真实行为。卡片要说明两种模式的差异、共享契约和各自的成功+失败路径。

优先覆盖 `org-health` 的真实端到端行为，尤其是 `e2e`、`serve`、`boss`、`builder`、`review` 链路。应从真实入口走到可观察结果，验证进程、HTTP、任务编排、构建产物或审查结果；不要把链路替换成只验证调用次数的 mock 测试。若确需隔离外部服务，mock 只能替代外部边界，核心流程仍须运行。

## 推荐卡片结构

```markdown
# <组件/行为>：<可观察结果>
labels: <priority>,<area>

背景：说明现状、风险，以及为什么不是重复主题。
范围：列出要改的文件/入口、双模式或 org-health 链路，以及明确不改的内容。
成功路径：给出输入、步骤和可断言的结果。
失败路径：给出错误/拒绝/超时/资源缺失等场景和可断言的结果。
实现与测试：说明预计至少 30 LOC 的有效实现/测试工作及隔离边界。

验收：`<可重复的本地命令>`
```

## 合格示例

```markdown
# org-health serve：双模式静态资源缺失返回稳定 404
labels: p1,backend:agy

背景：serve 的本地与 e2e 启动模式都应遵守同一 HTTP 资源契约。
范围：从真实 HTTP 入口请求存在文件和不存在文件；覆盖本地线程关闭与 e2e 服务退出，
不改端口占用和查询参数契约。
成功路径：请求存在文件返回 200 和文件内容；服务可启动、响应后可关闭。
失败路径：请求不存在文件返回 404，不列目录内容；错误响应后服务仍可关闭，
e2e 进程返回预期退出码。
实现与测试：为两个模式补充真实请求测试、清理逻辑和最小服务修正，预计 30+ LOC。

验收：`python3 openbot/examples/org-health-local/test_serve.py`
```

## 不合格示例

```markdown
# 补充空列表测试
在某测试文件增加一个 `[]` fixture，断言函数不抛异常且 README 有更新。
验收：`grep -q test .`
```

该示例同时违反 README-only、空输入边界模板、空壳测试和低于 30 LOC 预期等要求；它没有真实入口、成功路径、失败路径或可区分实现质量的验收标准。
