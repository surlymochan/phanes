# PROTOCOL — 协作、事件触发、门禁与授权

## 1. 总原则：少防御、多推进

- 这些机器是**测试环境**，只有用户一个人用。默认**直接做**，不要为低风险动作停下来问。
- 不为极端 corner case、理论上的安全风险、过度门禁耗时间。判据："这件事出错会不会让我们丢数据或泄露密钥？"不会，就先做，出了问题再修。
- 不写只复述实现的测试，不为低影响可逆改动叠加检查。完成与风险相称的检查就收工，不重复验证。
- 汇报要诚实：区分事实、推断、未知；没数据不说达标；绝对数字偏高时注明污染。

## 2. 高效协作

- **星型结构**：子会话只向统筹汇报。需要别的角色配合，请统筹转（或在信箱里 @ 对方，抄送统筹）。
- **消息格式**：`RESULT｜一句结论｜证据路径`、`ASK｜要决定的一件事｜我的建议`、`BLOCKED｜缺什么｜我已试过什么`。一条消息一件事，不贴长日志，给路径。
- **无变化不发**；要拍板才发；完成即发（不要攒到汇总）。
- **统筹收到消息后先做一件事**：判定"我自己能决定吗"——能就直接回"做"，不要把决策再抛给用户。
- 子会话不得把"用户已批准"转述给别人当授权；授权只来自用户在本会话里的原话。

## 3. 事件触发与定时任务（避免傻等）

**铁律：不用睡眠轮询。** 长任务必须有"完成即通知"的机制：

| 场景 | 做法 |
|---|---|
| 等远端日志出现新行/新结果 | `tools/watch.sh '<取当前状态的命令>'`：每隔 N 秒执行一次，输出变化就退出并打印新内容。用宿主的后台命令能力运行（Claude Code：`Bash run_in_background`；Codex：后台进程），退出即唤醒主会话 |
| 等 builder/tester 回消息 | 它们结束一轮会自动通知（Claude Code），或 `bash tools/msg.sh wait <role>` |
| 等 lane/run 结束 | `openswarm watch <id> --quiet`（终态/风险/停滞才有输出） |
| 周期性汇总 | ops 每小时一行（无异常也发），用 cron/定时任务触发，**不是**统筹轮询 |
| 兜底心跳 | 仅当没有事件源时用，间隔 ≥20 分钟，且只做"检查并上报变化"，不做重活 |

`tools/watch.sh` 内建：ssh 失败 3 次就报警退出、停滞超时（默认 45 分钟）报警退出、变化即退出。**每次唤醒后先核对原始日志再回应，再重新挂上等待器。** 同一时刻每个事件源只挂一个等待器。

**统筹的节奏**：派任务 → 立刻挂等待器 → 去做别的（设计下一步、审方案、写报告）→ 事件到来时响应。不要"派完就盯着"。

## 4. 评审门禁（用户已定的方向：放松）

通过条件 = **主逻辑可正常使用**。分两档：

- **BLOCKER（必须改，否则不通过）**：违反卡里写明的验收条件；正常输入下崩溃或结果错；数据丢失/损坏；明显的安全问题。
- **FOLLOW-UP（不挡通过，另记）**：卡没规定且不涉及上述后果的边界情形——极端输入、超大数、格式细节、缺少某个边界测试、风格。

由评审在输出里分档。FOLLOW-UP 进队列（限流，不要把 issue 刷爆）。放行后用保留测试 + 行为差分**抽检放过率**，放过率异常升高再收紧。上线前在历史卡上离线重评一次。

## 5. 授权：哪些必须先报用户（其余统筹自己定）

只有这几类，先给用户一句话 + 建议，等原话确认：

1. 把**密钥/凭据**用到新用途（例如用生产 MiniMax broker 密钥做额外查询、把密钥复制到新主机）。
2. 对**用户账号和组织**授权（GitHub App 权限、OAuth）。
3. **对外发布**：推送到公开仓库、发 issue/PR 评论、发消息给其他人。
4. **不可逆的数据操作**：删除生产数据库/备份、迁移（先备份）。
5. 拉高**金钱/额度**成本的大动作：MiniMax/Codex 额度大头消耗（先给估算）。

其余：改测试机配置、装软件、改 sshd、起停进程、新增沙箱、加 lane、改实验设计——统筹自己决定，事后一句话报告即可，并保留回滚方式。

## 6. 隔离与真值（实验有效性，不是"安全洁癖"）

这是**实验正确性**要求，不属于可放松项：

- 作者和评审运行在隔离沙箱内，读不到合并解、参考测试、历史 diff；出网只放行模型 API（探针清单见私仓 STATE.md）。
- 新主机/新 lane 进池前，tester 复测隔离并放行。Mac 机器可豁免隔离，但其结果标记 `isolated=false`，不计入结论。
- 真值 = 保留测试通过 + 与独立参考的行为差分；样本小只报配对差值与明细，不做显著性宣称。
- 公开仓库含参考解，污染排除不了：绝对通过率当上限看。

## 7. 变更记录

对主机的每个改动写：`what / where / verify / rollback`，追加到私仓 `STATE.md` 的"变更记录"或相应报告里。备份先于修改。
