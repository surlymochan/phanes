# PROTOCOL — 操作、授权与隔离

架构、角色、事件、容量和质量门禁以 [ARCHITECTURE.md](ARCHITECTURE.md) 为准；本文件只规定日常操作约束。

## 1. 执行与状态汇报

- 默认直接推进低风险、可逆操作；汇报区分事实、推断和未知。
- 只依据真实运行记录汇报状态，区分排队、已接收、已运行和已验证；没有回执时标为未知。
- 等待结束或会话轮次停止后，不宣称任务会自动恢复；恢复时重新核对在途任务和原始结果。
- 事件可能至少一次投递；消费者按稳定事件 ID 或游标去重。不得把接收回执当作结果验收。

## 2. 评审与授权

评审分级及放行条件见 [ARCHITECTURE.md §1.4](ARCHITECTURE.md)。审查针对固定版本；修复或提交链变化后，复核受影响内容。

以下事项先向用户说明建议并取得明确原话确认；其余已授权范围内的统筹由 Router 决定并事后报告：

1. 将密钥或凭据用于新用途，或复制到新的运行环境。
2. 扩大用户账号或组织授权，例如 GitHub App 权限或 OAuth。
3. 对外发布，包括推送公开仓库、发布 Issue/PR 评论或向他人发送消息。
4. 不可逆数据操作，例如删除生产数据库/备份或迁移生产数据；迁移前先备份。
5. 明显增加金钱或额度消耗的操作；先给出估算。

## 3. 实验隔离与真值

实验隔离和 L1 统计口径以 [ARCHITECTURE.md §2.4](ARCHITECTURE.md) 为准。执行实验前确认作者无法读取保留测试或参考真值；隔离不满足时将样本单列，不计入有效 L1 通过率。基础设施失败（包括模型服务错误）单独归类，不计入作者结果分母。

## 4. 环境变更记录

涉及运行环境的变更记录 `what / where（角色名） / verify / rollback`，并保留可执行回滚路径。记录中不得包含凭据或敏感个人信息。
