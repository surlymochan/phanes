# PROTOCOL — 操作、授权与隔离

架构、角色、事件、容量和质量门禁以 [ARCHITECTURE.md](ARCHITECTURE.md) 为准；本文件只规定日常操作约束。

## 1. 执行与状态汇报

- 这些机器是只有用户一人使用的测试环境：少防御、多推进，不为理论风险和极端边界情形叠加门禁；判据是会不会丢数据、泄密或产生不可逆影响。
- 默认直接推进低风险、可逆操作；汇报区分事实、推断和未知。
- 只依据真实运行记录汇报状态，区分排队、已接收、已运行和已验证；没有回执时标为未知。
- 等待结束或会话轮次停止后，不宣称任务会自动恢复；恢复时重新核对在途任务和原始结果。
- 事件可能至少一次投递；消费者按稳定事件 ID 或游标去重。不得把接收回执当作结果验收。
- 指标汇报写明口径与数据来源；失败先分类为能力、基础设施或环境，基础设施失败未清零或未重跑前不下"达成/未达成"结论；口径变更单独说明，不与旧口径数字直接比较。
- 用户的常设约束（语言、角色、模型下限、出网、授权范围）以共享记忆为准，新会话和子会话的 brief 必须引用；任务卡固定包含范围（含 worktree 外对象）、授权、输入（仓库内路径）、验收四段；转达用户批准时引用原话。
- 考核口径：按合并的有效变更与真实问题关闭数计，不按 issue、卡片或 PR 个数计；目标不得写成"消掉 N 个 issue"一类数量指标。

## 2. 评审与授权

评审分级及放行条件见 [ARCHITECTURE.md §1.4](ARCHITECTURE.md)。审查针对固定版本；修复或提交链变化后，复核受影响内容。

V4 原则：只有作者实际收到的内容（任务卡、可见测试）才能构成 BLOCKER；作者未收到的要求不能作为其违反验收条件的依据。

安全阀不得降级：验收命令、审查门禁、推送/合并前文件清单校验、合并前评审回执属于安全阀。替换必须同等或更强（例如换成新路径下的同一组测试），不得改成恒真命令、仅格式检查或自然语言。降级只能经用户原话确认，并按 §4 记录。为绕开某个问题而放宽检查，一律视为降级。门禁的失败结果必须改变流程（不放行、转修复或上报）；结果无人读取的检查视同不存在。

冲突处理：PR 与 main 冲突时，只走"合入最新 main → 执行端解决冲突、保留两边行为 → 重新审查净变更"，不得关闭 PR 后整批重做。关闭 PR 仅限复现判定问题已不存在，或用户裁定。

基础设施故障的处理：先原地修复（修环境、补验收、续跑），修不动才改派；改派也要从原提交继续，不得丢弃已有提交从头重做。验收结果缺失（例如缺少退出码）表示"未验证"，应在主机上对原提交补验，不能判成失败或基础设施故障。

公开边界：先声明可见性，再定门禁。每类对象（仓库、issue、project、PR、分支、提交信息、产物、文档、事件日志）的可见性，以私有可见性清单为唯一事实源，通用策略见 [VISIBILITY.md](VISIBILITY.md)。清单未声明的对象一律按公开处理，并拒绝写入。内容一旦推送到公开仓，或出现在 PR、issue、评论中，就已经公开了，因此门禁必须放在写入之前：
- 推送前：对相对 main 的全部提交扫描内容、文件名和提交信息。
- 写入前：开 PR、开 issue、评论、编辑，统一经过扫描封装，不得直接调用写接口。
- 合并前：CI 必需检查，作为最后兜底。
- 事后：巡检只读，只告警，处理动作经用户确认后执行。
命中即拒绝写入，按审查 FAIL 派修复；修复卡和日志只写位置和类别，不回显原文。具体词表只放在私有配置和 CI secret 中，公开仓库只保留通用规则。历史中已有的命中只做只读汇总，是否改写历史由用户决定。

以下事项先向用户说明建议并取得明确原话确认；其余已授权范围内的统筹由 Router 决定并事后报告：

1. 将密钥或凭据用于新用途，或复制到新的运行环境。
2. 扩大用户账号或组织授权，例如 GitHub App 权限或 OAuth。
3. 对外发布，包括推送公开仓库、发布 Issue/PR 评论或向他人发送消息。
4. 不可逆数据操作，例如删除生产数据库/备份或迁移生产数据；迁移前先备份。
5. 明显增加金钱或额度消耗的操作；先给出估算。

## 3. 实验隔离与真值

Mac 主机不做任何沙箱隔离（用户定的法则）：Mac 上的 lane 直接运行，不跑隔离探针。实验需要作者与保留测试隔离时，作者必须运行在看不到保留测试的 Linux 环境（独立主机或不挂载宿主目录的虚拟机）；在 Mac 上直接运行的实验样本标记为未隔离，单独报告。

实验隔离和 L1 统计口径以 [ARCHITECTURE.md §2.4](ARCHITECTURE.md) 为准。执行实验前确认作者无法读取保留测试或参考真值；隔离不满足时将样本单列，不计入有效 L1 通过率。基础设施失败（包括模型服务错误）单独归类，不计入作者结果分母。

## 4. 环境变更记录

涉及运行环境的变更记录 `what / where（角色名） / verify / rollback`，并保留可执行回滚路径。记录中不得包含凭据或敏感个人信息。

共享配置（沙箱、代理、凭证、模型配置）先在单台主机变更并实测，通过后再推广到全体；共享凭证只从单一来源同步并按哈希核对。

机群环境基线：执行机的期望环境（运行时与工具链、包装脚本、凭证位置、语言与区域设置、登录与非登录 shell 的 PATH、安全加固项）以基线清单为唯一事实源，由幂等收敛脚本落实，并通过漂移巡检定期核对。在任何一台主机上发现的环境问题，修复步骤必须写进基线清单和收敛脚本，并当场对全机群执行，不得只修出问题的那一台。新机器或重建后的机器必须先收敛并通过巡检，才能接单。调度按主机实测能力匹配任务，不按主机名硬编码。
