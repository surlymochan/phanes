# PROTOCOL — 协作、事件触发、门禁与授权

## 1. 总原则：少防御、多推进

- 这些机器是**测试环境**，只有用户一个人用。默认**直接做**，不要为低风险动作停下来问。
- 不为极端 corner case、理论上的安全风险、过度门禁耗时间。判据："这件事出错会不会让我们丢数据或泄露密钥？"不会，就先做，出了问题再修。
- 不写只复述实现的测试，不为低影响可逆改动叠加检查。完成与风险相称的检查就收工，不重复验证。
- 汇报要诚实：区分事实、推断、未知；没数据不说达标；绝对数字偏高时注明污染。

## 2. 协作

Boss 兼 RSI，定义任务和验收，使用 swrm 按需派发 build lane 与独立 review lane。对抗测试在 lane 中进行，受控测试执行器 `tools/review_run.py` 与 evalid 留存证据；巡检使用脚本。临时 subagent 只承担有界任务。Boss 核对原始结果并决策，授权以用户原话为准。

## 3. 等待与定时

- Claude Code：后台运行 `openswarm watch <run-id> --quiet`，用 Monitor 等待；到期后核对状态并按需重挂。
- Codex 桌面版：在当前轮次原生等待 watch；空闲兜底使用定时心跳，恢复后核对在途任务及原始结果。
- 不造 bridge、信箱或 watchdog。等待结束或轮次停止后，不宣称会自动唤醒；恢复时重新核对并等待。

## 4. 评审门禁（用户已定的方向：放松）

通过条件 = **主逻辑可正常使用**。分两档：

- **BLOCKER（必须改，否则不通过）**：违反卡里写明的验收条件；正常输入下崩溃或结果错；数据丢失/损坏；明显的安全问题。
- **FOLLOW-UP（不挡通过，另记）**：卡没规定且不涉及上述后果的边界情形——极端输入、超大数、格式细节、缺少某个边界测试、风格。

V4 原则：只有作者实际收到的内容才能形成 BLOCKER；未送达作者的要求不能作为其违反验收条件的依据。由评审在输出里分档。FOLLOW-UP 进队列（限流，不要把 issue 刷爆）。放行后用保留测试 + 行为差分**抽检放过率**，放过率异常升高再收紧。上线前在历史卡上离线重评一次。

## 5. 授权：哪些必须先报用户（其余统筹自己定）

只有这几类，先给用户一句话 + 建议，等原话确认：

1. 把**密钥/凭据**用到新用途（例如用生产 MiniMax broker 密钥做额外查询、把密钥复制到新主机）。
2. 对**用户账号和组织**授权（GitHub App 权限、OAuth）。
3. **对外发布**：推送到公开仓库、发 issue/PR 评论、发消息给其他人。
4. **不可逆的数据操作**：删除生产数据库/备份、迁移（先备份）。
5. 拉高**金钱/额度**成本的大动作：MiniMax/Codex 额度大头消耗（先给估算）。

其余：改测试机配置、装软件、改 sshd、起停进程、新增沙箱、加 lane、改实验设计——统筹自己决定，事后一句话报告即可，并保留回滚方式。

## 6. 隔离与真值（实验有效性，不是"安全洁癖"）

这是**实验正确性**要求，不属于可放松项：

- **Mac 机器（gocc、本机）全面取消沙箱隔离（用户定，2026-11-07）**：不装 bwrap，pi 用直连二进制不用 `pi-isolated`，Codex 用 `danger-full-access`，不做隔离探针。Mac 上可以跑任何 lane 工作（实现、审查、fixture、受控测试）。
- Linux 机器上，L1 实验的作者和评审运行在隔离沙箱内，读不到合并解、参考测试、历史 diff；出网只放行模型 API（探针清单见私仓 STATE.md）。新 Linux 主机进池前跑 `tools/isolation_probe.sh`。
- Mac 上跑的 L1 实验臂，作者读得到同机的保留测试：结果记 `isolated=false`，单独报告，不并入 L1 通过率。这是数据口径，不是隔离机制。
- 真值 = 保留测试通过 + 与独立参考的行为差分；样本小只报配对差值与明细，不做显著性宣称。
- 公开仓库含参考解，污染排除不了：绝对通过率当上限看。

## 7. 变更记录

对主机的每个改动写：`what / where / verify / rollback`，追加到私仓 `STATE.md` 的"变更记录"或相应报告里。备份先于修改。
