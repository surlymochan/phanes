## B1 / B2 / B3 逐条映射（对应第 2 轮 review 的三条 BLOCKER）

### B1 — 队列不可读时限制补卡重试（记录成功铸卡或等待权威水位恢复）

- `tools/lane-autodispatch/autodispatch.py:23` `QUEUE_UNREADABLE_REFILL_MAX`
  （`AD_QUEUE_FAIL_REFILL_MAX`，默认 3）：连续队列读失败次数的上界。
- `tools/lane-autodispatch/autodispatch.py:18` `TARGET`（`AD_TARGET`，默认 20）：池见底时补到
  target 而不是只补到 low。
- `tools/lane-autodispatch/autodispatch.py:1709` `pool_level(state)`：估算水位 =
  上次权威水位 `state["_ready"]` + 之后铸出的张数 `state["_minted"]`；从未成功读过队列时返回
  `None`（水位未知）。
- `tools/lane-autodispatch/autodispatch.py:1719` `refill_on_unreadable_queue(state)`：
  失败计数 +1；水位未知 → 一次也不铸；超过上界 → 不再铸、等待权威读；否则按估算水位补卡，
  并把**本次成功铸出的张数**记进 `state["_minted"]`（下一轮的估算水位随之抬高，不会重复补
  同一批）。
- `tools/lane-autodispatch/autodispatch.py:1599` `tick()`：队列读失败时改为调用上面的有界补卡，
  并留下 `queue error` / `queue unreadable #N` 日志。
- `tools/lane-autodispatch/autodispatch.py:1641`：一次成功读队列后 `_ready` / `_minted` /
  `_queue_failures` 归位（权威水位取代估算值）。
- `tools/lane-autodispatch/autodispatch.py:959-960`：`lanes-status.json` 增加
  `_queue_failures` 与 `_minted`；队列读不出来时还有 `_ready_estimate`（第 1602 行），
  看门狗能看出水位是权威值还是估算值。

测试：

  `test_a_persistent_queue_failure_mints_within_a_bound_and_then_waits`：**tick 级**持续读取失败

  铸出的卡计入水位（`_minted == 1`，估算水位 5 → 6）。

  水位未知时一次也不铸。

  队列恢复可读后失败计数清零、水位回到权威值。

### B2 — 隔离卡片时避免覆盖已有同名文件（两份内容都保留）

- `tools/lane-autodispatch/autodispatch.py:1690` `move_without_overwrite(source, destination)`：
  用 `O_CREAT|O_EXCL` 独占预留文件名（两个 AD 进程不会抢到同一个空名），目标已存在时改用
  `.1`、`.2` … 后缀，旧卡内容原样保留。
- `tools/lane-autodispatch/autodispatch.py:1660` `card_defect(text, strict=False)`：一张车道跑不
  起来的卡（缺 `# ` 标题、缺 `labels:` 行、缺正文）带原因隔离；repo backlog 的卡
  （`docs/backlog/next/*.md`）另须满足 planner 契约（正文两行以上 + `验收：` 行，即
  `tools/check-ad-ready-target.py` 的 `is_thin_card`）。本地 backlog 是运维投递箱：只要车道
  能跑就铸出（保住 main 上 impl 卡投递契约，见 `tools/tests/test_impl_card_task_book.py`）。
- `tools/lane-autodispatch/autodispatch.py:1797`（`replenish()` 的本地卡循环）：不合规的卡隔离到
  `backlog/rejected/` 时走 `move_without_overwrite`（不再用 `os.replace` 覆盖同名旧卡）；
  `:1803` 铸出后移入 `backlog/filed/` 同样不覆盖同名旧卡。
