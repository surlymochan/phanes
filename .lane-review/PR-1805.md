本轮改动（文档 + 配置项容错，份额规则本身不改）：

1. `tools/lane-autodispatch/README.md` 新增「队列优先级类与保底份额（Refs #1794）」一节：
   - **配置项与默认值**：`AD_VERIFY_SHARE_ENABLED`（默认 `0`，总开关）、`AD_VERIFY_SHARE`
     （默认 `0.2`，保底比例）、`AD_VERIFY_MIN`（默认 `1`，保底车道数下限）；
   - **部署启用方式**：① 把仓库镜像同步到 box 运行时
     （`cp /workspace/phanes-repo/tools/lane-autodispatch/autodispatch.py ~/phanes-ctl/bin/autodispatch.py`），
     ② 在 AD 的启动环境里 `export AD_VERIFY_SHARE_ENABLED=1`，③ `~/phanes-ctl/bin/start-control-plane`
     重启 AD 循环；**默认关闭时派发行为与本策略之前完全一致**；
   - **份额算法**（按空闲车道与在途构成，不是全局静态数）与**优先级合成顺序**；
   - **日志**：份额生效/让行（`queue share: <lane> prefers verify|work (...); other class yields`）
     与派发类别（`queue share: dispatched <class> #<n> on <lane>`）。
2. `docs/ctl-boot.md` 新增「AD queue share for verify cards (Refs #1794)」一节：box 侧的
   配置表与启用步骤（部署口径与 README 一致）。
3. `tools/autodispatch-backend-fallback.md` 新增「Composition with the queue share policy
   (Refs #1794)」：份额与既有排序规则（own pin → unpinned → cross-pin → prio → 号）的**显式
   合成顺序**：类别准入 → pin 类别 → 同类别内 prio/号；类别准入只改写「验证类 vs 工作类」的先后，
   pin/prio/号的相对次序不变（稳定排序）。
4. **配置值容错**（`tools/lane-autodispatch/autodispatch.py`）：新增 `env_number()`，`AD_VERIFY_SHARE`
   / `AD_VERIFY_MIN` 写错时回退默认值，而不是让 AD 在 import 时崩掉（新引入的配置项不能把整个
   派发循环带崩）；回归测试 `test_share_configuration_falls_back_to_the_default_on_a_bad_value`。
