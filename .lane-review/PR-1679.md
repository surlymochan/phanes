## 上一轮 4 个 BLOCKER 的逐条修复与对应测试

### B1：没有可信恢复时间 / 不查窗口状态就重投

- **改动**：
  - `openswarm/lib/dispatch/failure_class.py`：新增窗口状态口径——`probe_state(probe)`
    （探针回答 `{"exhausted": true|false}` → `exhausted`/`open`，没有回答 → `unknown`）、
    `window_state(probe, reset_passed)`（探针回答优先；探针没回答时「恢复时间已过」才算
    窗口恢复；其余 `unknown`）、`reset_seconds_from_text(text)`（从 run 文本读恢复时间：
    `resets in 2h13m`、`resets in 900`、`Retry-After: 120`）。
  - `openswarm/lib/dispatch/engine.py`：`budget_window_reset(info)` 按
    **run 的 `resets_at` → 探针的 `resets_at` → run 文本的恢复时间** 取可信恢复时间；
    `requeue_budget_cards()` 重投前先看窗口**当前**状态：探针报 `exhausted: true` 或没有
    回答（状态无法确认）就**继续挂起**并把 `requeue_at` 往后推，只有 `exhausted: false`
    （或恢复时间已过）才贴回 `lane-ready`；新增 `budget_max_hold_s`（默认 6h）作为「状态
    一直无法确认」时的挂起上限，到点回到 `lane-failed`（终态，不会永远占着 `in-progress`）。
  - `tools/lane-autodispatch/autodispatch.py`：同一口径——`budget_window_probe()`（探针
    读法 `AD_BUDGET_PROBE_CMD`，输出 JSON）、`budget_window_state()`、
    `budget_window_reset(info)`（run `resets_at` → run 文本 → 探针 `resets_at`）、
    `budget_reset_seconds(text)`；`requeue_budget_cards()` 同样按窗口状态决定重投，
    状态无法确认时继续挂起（`AD_BUDGET_REQUEUE_MAX_HOLD`，默认 6h）。
  - 真实执行器的 result.json **没有顶层 `resets_at`**（`openswarm/bin/openswarm` 只写
    `status`/`error_class`/`summary`），所以「无 `resets_at` 的收割」是主路径，测试按这个
    形状写。
- **对应测试**：
  - `openswarm/tests/test_dispatch_failure_class.py`：`WindowStateTests`（探针回答优先、
    恢复时间已过才算开、无回答 = unknown）、`WindowResetTextTests`（run 文本的恢复时间）。
  - `openswarm/tests/test_dispatch_engine.py::BudgetFailureHarvest`：
    `test_a_run_without_a_reset_time_waits_for_the_window_probe`、
    `test_the_run_text_may_name_the_window_reset`、`test_the_probe_may_name_the_window_reset`、
    `test_a_closed_window_keeps_the_card_held`、`test_an_unknown_window_keeps_the_card_held`、
    `test_a_card_held_on_an_unknown_window_expires_into_lane_failed`、
    `test_the_tick_releases_the_lane_and_requeues_the_card`（tick 级）。
  - `openswarm/tests/test_autodispatch.py::BudgetFailureTests` / `BudgetFailureTickTests`：
    `test_a_closed_window_keeps_the_card_held`、
    `test_an_unknown_window_keeps_the_card_held`、
    `test_a_card_held_on_an_unknown_window_expires_into_lane_failed`、
    `test_the_run_text_may_name_the_window_reset`、
    `test_the_tick_holds_the_card_frees_the_lane_and_requeues_it_when_the_window_is_back`
    （tick 级）。

### B2：重投后 budget 失败次数归零，次数上限失效

- **改动**：两个收割器都把每张卡的 budget 失败次数单独记在 state 的 `_budget_tries`，
  **重投只删 `_budget_requeue` 里的挂起记录，不删计数**；下一次同卡再撞窗口时
  `tries = 计数 + 1`。终态清理：贴 `lane-failed`（次数到上限 / 挂起超时）、卡被关掉、
  已经出了 PR、以及正常收尾的 `mark_done()`（卡不在 `_budget_requeue` 里时）都会清掉这张卡
  的计数。engine：`openswarm/lib/dispatch/engine.py` 的 `hold_budget_card()` /
  `requeue_budget_cards()` / `mark_done()`；AD：`tools/lane-autodispatch/autodispatch.py` 的
  `hold_budget_card()` / `requeue_budget_cards()` / `mark_done()`。
- **对应测试**（两个收割器各一条，跨重投的连续失败）：
  - `openswarm/tests/test_dispatch_engine.py::BudgetFailureHarvest::test_the_budget_failure_count_survives_a_requeue`
    （失败 1 次 → 窗口恢复重投 → 再失败计数为 2 → 再恢复时次数到上限 → `lane-failed` 且计数被清）。
  - `openswarm/tests/test_autodispatch.py::BudgetFailureTests::test_the_budget_failure_count_survives_a_requeue`
    （同上，AD 侧）。

### 重基回归：budget 分支返回值与 tick 期望的结构不一致

- **改动/核查**：`tools/lane-autodispatch/autodispatch.py` 的 `finish()` 在 budget 分支返回
  `{"done": True, "status": "budget-held", "error": None, "missing": []}`（tick 用
  `result.get("done")` / `result.get("error")`），其余分支同样是 dict；engine 侧
  `finish()` 返回 bool，tick 用 `bool(self.finish(...))`。两个收割器的 tick 都不再对
  budget 分支的返回值调用 `.get` 于非 dict 值。
- **对应测试**：
  - `openswarm/tests/test_autodispatch.py::BudgetFailureTickTests::test_the_tick_holds_the_card_frees_the_lane_and_requeues_it_when_the_window_is_back`
    （真实 AD tick：收割后车道释放、挂起记录在 state 里、窗口恢复后下一轮贴回 `lane-ready`）。
  - `openswarm/tests/test_dispatch_engine.py::BudgetFailureHarvest::test_the_tick_releases_the_lane_and_requeues_the_card`
    （真实 engine tick：`harvest()` 后 `state` 里没有车道槽位、`requeue_budget_cards()` 在
    同一轮把卡贴回 `lane-ready`）。
