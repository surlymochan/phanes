## 离线查看差异

上一轮的功能提交与其父提交都在本地对象库，可直接比对：

```sh
git diff e1e838a0a8408da0f2f0db5775b573d65f51414bf..6665844026b189c1e3e3534234d837bb8c92f181
git diff --stat e1e838a0a8408da0f2f0db5775b573d65f51414bf..6665844026b189c1e3e3534234d837bb8c92f181
git show --stat 6665844026b189c1e3e3534234d837bb8c92f181
```

本轮的新头由 AD 推回 PR 分支后，用同样的方式比对：

```sh
git diff main...<新头>
git diff --stat main...<新头>
```

新头未推送之前，车道 worktree 里就是本轮的完整改动，可直接查看：

```sh
git -C <lane worktree> status --short
git -C <lane worktree> diff --stat
```

## 本轮相对上一轮的修正

1. **误提交的编译产物**：上一轮的头提交里带了两个二进制 `.so`（`openswarm/tests/.dde4dfdffef7b7b2-00000000.so`、
   `openswarm/tests/.dde4dffff7d7f4-00000000.so`，各约 4.4 MB）。它们不是本卡的产物，已从新头剔除；
   仓库里早先被同类产物污染的两个 `.so`（`openswarm/tests/.dde4df7ffebedc3d-00000000.so`、
   `openswarm/tests/.dde4df7ffeffd7b8-00000000.so`）也一并删除，并在仓库的 `.gitignore` 里加上 `*.so`，
   以后这类产物不会再被任何 `git add -A` 带进提交。
2. **审查阻塞项（取差异的途径）**：`openswarm/lib/dispatch/engine.py` 的 `review_item` 在 `gh pr diff` 为空时，
   改用 `local_pr_diff()` 从本地仓库取差异——PR 分支已被 fetch 到 `refs/fleet/<lane>`，基线取 base 分支的
   fork point（`merge-base`）。取不到就仍然为空，绝不编造差异。这样即使 GitHub 不可达，审查任务里也带着
   PR 的真实差异，审查者不再需要自己联网取 diff。
3. **只读口径**：`read_lane_state` 只收带卡片号的条目，home 里的探测状态（`state.json`）不会被当成车道状态读进来。
